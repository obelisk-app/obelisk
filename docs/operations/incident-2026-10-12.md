# Incident 2026-10-12: obelisk.ar down, then the desktop crash

Two unrelated failures, one after the other. Both are fixed on `fix/composer-update-depth` (commits `fb4d70a0` and `53e5be70`), which production was deployed from on 2026-10-12.

## 1. The site served 502: `next start` crash-looped

**Symptom.** obelisk.ar returned 502. `pm2 ls` showed `obelisk-dex` with an uptime of 0 s and more than 240,000 restarts.

**Cause.** pm2 had restarted the app from its saved state (a resurrect) without `SWC_NATIVE_BINDING_CACHE`. `next start` loads `next.config.ts`, which loads `@swc/core` through the next-intl plugin. On this box `~/.cache` is a symlink, so SWC refuses to use it:

```
Error: Failed to load native binding
  ERR_SWC_NATIVE_CACHE: validate cache root /root/.cache: cache root contains a non-directory or symlink
```

The build in `.next/` was fine. Only the server failed to start.

**Fix.**
- `ecosystem.config.js` sets `SWC_NATIVE_BINDING_CACHE=/root/obelisk-dex/.swc-native-cache` in the app's env.
- `scripts/deploy.sh` exports it for the build and restarts with `pm2 restart --update-env`.
- `.swc-native-cache/` is git-ignored.
- `pm2 save` was run with the variable set, so the next resurrect keeps it.

**Watch for.** Deploying from a tree without that commit (main, until the branch is merged) brings this back on the next pm2 resurrect.

## 2. The desktop app crashed with React error #185

**Symptom.** On desktop, opening a channel (often the second one) replaced the chat with "Something broke on this screen" and `Minified React error #185` (maximum update depth exceeded). It happened only in the production build, never in `next dev` or vitest, and not on every load.

**Cause.** The operator subscribers `subscribeLayout` (`src/services/relay/channel-layout.ts`), `subscribeBranding` (`relay-branding.ts`) and `subscribeRelayRoles` (`relay-roles-sync.ts`) call themselves by name, to retry once the bridge exists. Because of that self-reference, the production webpack bundle inlines each one into its export getter:

```js
r.d(t, { Fk: () => function e(t, r, n) { /* subscribeLayout */ } })
```

Every read of the import therefore returns a new function. `useRelayScopedValue` (`src/hooks/relay/operator/useRelayScopedValue.ts`) had `subscribe` in its effect dependencies, so on every render it:

1. saw a "new" `subscribe` and re-ran the effect (unsubscribe, then subscribe again, which opens a new kind 30078 REQ);
2. had the subscriber deliver its cached value synchronously, as a freshly parsed object;
3. stored it with `setLatest`, which rendered again and started over.

One page load opened 7,712 kind 30078 REQs before React stopped at its nested-update limit.

**Fix.** The hook reads `subscribe` once, on mount (`useState(() => subscribe)`), and no longer lists it as a dependency. The earlier guards from `7d11e337` remain: an equal value does not set state, and the synchronous first delivery is deferred to a microtask. That commit's message guessed that something above the sidebar was looping; the real driver was the unstable `subscribe` identity described here.

**Regression test.** `tests/hooks/relay/operator/useRelayScopedValue.test.tsx`, "a new subscribe function each render does not resubscribe", passes a fresh `subscribe` on every render, the way the production bundle does. It fails without the fix.

**Verification.** A production build, driven headlessly through all 12 channels of `wss://public.obelisk.ar` three times: no crash, 6 to 8 kind 30078 REQs per run. The same steps against the old build crashed after 7,712.

### Lessons

- **Check subscription identity in the failing bundle.** These subscriber exports were observed changing identity in the affected production build. This hook can capture its subscriber once because each caller always uses the same subscription implementation; relay and author inputs remain reactive. Do not generalize that workaround to callbacks whose behavior must change with props or state.
- **Prod-only #185s need a prod build.** A #185 that only reproduces in production needs a production build to debug. Read the minified chunk at the stack frame the error names.
- **Reproducing needs a whitelisted key.** A fresh key is not on `public.obelisk.ar`'s whitelist and sees no channels. Drive the app as an admitted key, here the bot key (`BOT_NSEC` in `.env.local`), with Playwright from `node_modules`.
- **Prod held unreviewed code.** The build that crashed also contained uncommitted `[185]` debug logging (`globalThis.__d185`). Someone had built production from a working tree with changes that were never committed. Build production only from a clean, committed tree.
